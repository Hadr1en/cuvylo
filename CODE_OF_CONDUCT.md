# Code de conduite

Cuvylo aide des personnes à chercher un emploi, un moment souvent stressant. Les échanges autour du projet doivent être à cette image : accueillants, patients et respectueux, pour tout le monde.

Ce code s'applique partout où le projet est représenté : issues, pull requests, relectures de code, discussions et tout échange public lié à Cuvylo.

## Ce que l'on attend

- Être bienveillant et patient, en particulier avec les personnes qui débutent ou qui contribuent pour la première fois.
- Critiquer le code et les idées, jamais les personnes ; argumenter, proposer une alternative.
- Accepter de ne pas avoir raison, reconnaître une erreur et en tirer parti.
- Respecter la vie privée : ne jamais publier le CV, les coordonnées ou toute donnée personnelle de quelqu'un, y compris dans un rapport de bug.
- Garder en tête les principes du projet : honnêteté envers les utilisateurs, pas de promesse trompeuse, pas de collecte de données.

## Ce qui n'est pas accepté

- Les insultes, le harcèlement, les menaces, les moqueries et les attaques personnelles.
- Les propos ou images discriminatoires, sexualisés ou violents, quel qu'en soit le motif : origine, genre, orientation, handicap, âge, apparence, religion, niveau d'expérience, etc.
- La divulgation d'informations privées d'autrui sans son accord.
- La publicité, le spam et toute utilisation du projet à des fins commerciales contraires à sa [licence](LICENSE.md).
- Insister après qu'on vous a demandé d'arrêter.

## Signaler un problème

Si vous êtes victime ou témoin d'un comportement contraire à ce code, signalez-le au mainteneur :

- pour un message ou un commentaire précis, utilisez le menu « … » → *Report content* de GitHub, qui prévient aussi les modérateurs de GitHub ;
- sinon, ouvrez une issue en restant factuel et sans y recopier de données personnelles ; le mainteneur la traitera en priorité.

Chaque signalement est examiné avec discrétion. Pour une faille de sécurité, utilisez plutôt le [signalement privé](https://github.com/Hadr1en/cuvylo/security/advisories/new).

## Ce qui peut se passer

Selon la gravité, le mainteneur peut : demander de corriger ou retirer un message, masquer ou supprimer un contenu, verrouiller une discussion, refuser une contribution, ou bloquer une personne du projet, temporairement ou définitivement.
